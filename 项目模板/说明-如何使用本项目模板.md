# 项目模板包使用说明

> 这套模板是一套人机协作开发治理机制（见 `../主控卡.md` 等三份权威文档）的落地件。每个 `.template` 文件对应一个规范项目里应有的文档。
> 你把**主控卡**（`../主控卡.md`）交给担任主控的 AI，AI 按需取用模板与示例，就能产出一个
> 结构规范、可维护、可回滚、**不堆积中间文件**的项目。

---

## 入口与喂法

**不要把模板和整套示例一起喂给 AI。** 正确入口是 `../主控卡.md`：

1. 主控每次会话只读必读三样+现场：主控卡 + `../放权机制.md` + 当前项目的 AGENTS.md + PROGRESS.md
   （PROGRESS 头部有"当前授权模式"行）
2. 到"要产出某文档"的节点，才按主控卡的按需取用表读对应模板 + 对应示例**各一份**
3. 大需求开工时，主控读 `../智能体角色定义.md` 为 planner/worker/checker 各生成一份专属
   投影 prompt（`.qoder/agents/`）——子代理不直接读角色定义

规则全文见三份权威文档（`../主控卡.md`、`../放权机制.md`、`../智能体角色定义.md`）。本说明不复述规则，
只列清单。

## 模板文件清单

### A 区：常驻模板（`docs/` 根）

| 模板文件 | 角色 |
|---|---|
| `AGENTS.md.template`（放项目根） | 项目宪法 + 架构总览活地图 |
| `docs/PROGRESS.md.template` | 进度现场（含 checker 结论区） |
| `docs/backlog.md.template` | 待办/顺手想改/未决产品决策登记处 |
| `docs/decisions/ADR-模板.md.template` | 永久决策日记 |
| `scripts/hooks/`（放项目根） | 机械门禁三钩子（激活见 AGENTS 模板提交纪律节） |

### B 区：归档件模板（`docs/archive/归档件模板/`）

> 大需求专属过程文档的空表。**执行期建在 docs/ 根，完成后整体移入
> `docs/archive/<大需求名>-大需求/`。** 新开一个大需求时从这里取模板填。

| 模板文件 | 角色 |
|---|---|
| `PLAYBOOK.md.template` | 大需求总控手册（含附录 M 机械检查清单——M-测试/M-密钥/M-依赖为内置占位 + 三角色权限表） |
| `MIGRATION_PLAN.md.template` | 分步迁移计划（中小型大需求可并入 PLAYBOOK，见两模板开头的合并条款） |
| `ARCHITECTURE.md.template` | 现状地图 + 目标架构（深度快照） |
| `ROADMAP.md.template` | 产品体检 + 路线图 + 决策菜单（仅产品类大需求） |
| `manual-checklist.md.template` | 人工验收清单（大需求专属，随需求归档） |
| `审计报告模板.md.template` | 各类审计报告（含 checker 的 verdict 也用此结构） |

### C 区：归档说明（`docs/archive/`）

| 模板文件 | 角色 |
|---|---|
| `归档说明.md.template` | 归档区使用规则 |

## 命名约定

- 模板文件后缀 `.template` 是防止被当成项目正式文档误读；使用时去掉后缀，放到对应位置
- `docs/decisions/` 下的 ADR 编号递增，只增不改、永不归档
- checker 的 verdict 命名：`docs/audits/check-<步骤或阶段>-<日期>.md`，只追加
- 大需求过程文档按 `docs/archive/<大需求名>-大需求/` 归档，封存不删；历史归档件不改名
- 每次只会有一个"正在做的大需求"；一次多个大需求时，每个各有独立的 archive 文件夹

新项目初始化：运行 `项目模板/scripts/init-project.sh <目标目录> <项目名>` 盖章式生成 `.aiops/` 骨架；机械门禁激活：`git config core.hooksPath .aiops/scripts/hooks`。
