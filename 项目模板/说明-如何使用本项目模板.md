# 项目模板使用说明

## 安装

在本仓库根目录运行：

```sh
项目模板/scripts/init-project.sh <目标目录> <项目名> [宿主标识]
```

安装器会生成可见的 `guanjia/` 目录，并在目标项目的 `AGENTS.md` 中合并一个带 `GUANJIA BEGIN/END` 标记的短入口。它会保留原有规则、旧 `.aiops/` 和业务文件；发现同名受管文件被人工改写时会停止，不会静默覆盖。

## 第一次使用

```sh
cd <目标目录>
node guanjia/bin/guanjia.mjs doctor --json
node guanjia/bin/guanjia.mjs status --json
```

若没有 Git，状态和交接仍可用，但版本备份和提交检查不可用。若 `doctor` 显示宿主 hook 为 `unverified`，表示还没有真实事件探针证据，不要把它理解为自动恢复已启用。

Windows PowerShell 下不要在任意目录直接运行相对路径 `node guanjia/bin/guanjia.mjs`；相对路径会按当前目录解析。安装后可使用包装器，它会自动定位项目根目录：

```powershell
& .\guanjia\guanjia.ps1 migrate --from aiops --dry-run --json
& .\guanjia\guanjia.ps1 hooks install
& .\guanjia\guanjia.ps1 probe --host zcode --nonce zcode-demo-001
```

从其他目录调用时，请使用项目的绝对路径：`& "<项目绝对路径>\guanjia\guanjia.ps1" status --json`。也可以先 `Set-Location "<项目绝对路径>"`，再直接调用 Node 核心入口。

若要开启提交前检查：

```sh
node guanjia/bin/guanjia.mjs hooks install
```

它会保留已有 `pre-commit` 并先运行原检查；已有 `core.hooksPath` 不会被静默替换。ZCode/Codex 的自动入口要在真实客户端触发探针后才算生效：

```sh
node guanjia/bin/guanjia.mjs probe --host zcode --nonce zcode-demo-001
```

旧项目升级先预览：

```sh
node guanjia/bin/guanjia.mjs migrate --from aiops --dry-run --json
node guanjia/bin/guanjia.mjs migrate --from aiops --apply --json
```

`--apply` 只复制历史资料到 `guanjia/archive/legacy-aiops/`，保留原 `.aiops/`，遇到目标冲突就停止。卸载先运行 `uninstall --dry-run --json`，初版不会自动删除状态、证据和用户修改。

## 交接与恢复

用户说“暂停”时，将任务转为 paused；新窗口运行 `resume --json` 只会汇报暂停，不会自动写文件。用户明确恢复后才继续。需要换工具或窗口时运行：

```sh
node guanjia/bin/guanjia.mjs checkpoint --input '{"summary":"已完成什么","next_action":"下一项动作"}'
node guanjia/bin/guanjia.mjs handoff
```

不需要每次重新发送长开启提示词；手动后备入口是读取 `guanjia/START.md`。

## 不要误解的边界

`guanjia/HANDOFF.md` 是自动生成的可读快照，不是第二份状态权威；发生分歧时以核验后的 `state.json` 和实际 Git 现场为准。文件存在不等于宿主已经加载插件，也不等于模型理解了全部历史。
